# Pro Git — Glossary

Key terms in alphabetical order, each with the chapter it comes from (A–C = appendices).

- **@{upstream} / @{u}**: shorthand for the current branch's upstream branch. (Ch3)
- **alias**: a `git config alias.X` shortcut. A leading `!` runs an external command. (Ch2)
- **annotated tag**: a full checksummed tag object with tagger, date and message, optionally GPG-signed. The book recommends it over lightweight tags. (Ch2)
- **author vs committer**: the person who wrote the change vs the person who last applied it. (Ch2)
- **bare repository**: a repository with no working directory, used as a shared meeting point. By convention its name ends in `.git`. (Ch4)
- **benevolent dictator / lieutenants**: a workflow where lieutenants merge topics for their areas and the dictator merges the lieutenants' branches into the reference repo. (Ch5)
- **bisect**: binary search through history for the commit that introduced a bug. (Ch7)
- **blob**: an object holding file contents only, with no filename. (Ch10)
- **branch**: a lightweight movable pointer to a commit, stored as a 41-byte file (40-char SHA-1 plus newline). (Ch3)
- **bundle**: a single file holding what a push would send. It can be cloned or fetched from. (Ch7)
- **clean / smudge filter**: attribute-driven filters. Clean runs when content is staged, smudge when it is checked out. (Ch8)
- **commit object**: points to a top-level tree and its parents, and records author, committer and message. (Ch10)
- **content-addressable filesystem**: a key-value store whose key is a hash of the content. This is what Git is underneath. (Ch10)
- **core.autocrlf**: line-ending conversion: `true` (CRLF on checkout), `input` (convert to LF on commit only) or `false`. (Ch8)
- **credential helper**: an external `git-credential-<name>` program that answers get/store/erase requests. Built-ins include `cache` and `store`. (Ch7)
- **dangling object**: an object no ref or other object points to. `git fsck` reports these. (Ch10)
- **dcommit**: `git svn dcommit`, which makes one SVN commit per local commit and rewrites the local commits with a `git-svn-id`. (Ch9)
- **detached HEAD**: HEAD holds a raw SHA-1 instead of a branch name, e.g. after checking out a tag. New commits there belong to no branch. (Ch2, Ch10)
- **double dot (A..B)**: commits reachable from B but not from A. (Ch7)
- **DVCS**: distributed VCS, where every clone mirrors the full history and so is a full backup. (Ch1)
- **export-ignore / export-subst**: attributes that leave a path out of `git archive`, or expand `$Format:...$` placeholders in it. (Ch8)
- **fast-forward**: a merge where the target is directly ahead, so Git only moves the pointer. (Ch3)
- **fork (GitHub)**: your writable copy of a project in your own namespace. (Ch6)
- **git fast-import**: reads a text stream of commits and files on stdin and writes Git objects. Used by custom importers. (Ch9)
- **Git Fusion**: a Perforce server-side product that exposes depot paths as read-write Git repos. (Ch9)
- **git-p4**: a client-side bridge between Git and Perforce. (Ch9)
- **git-remote-hg**: a remote helper that lets normal clone/fetch/push work against Mercurial. (Ch9)
- **git-shell**: a restricted login shell that allows only Git operations over SSH. (Ch4)
- **GitHub Flow**: fork, topic branch, commit, push, open a PR, discuss and iterate, merge. (Ch6)
- **gitk / git-gui**: GUIs bundled with Git, for browsing history and for crafting commits. (App A)
- **gitlink (mode 160000)**: a tree entry that records a submodule's commit instead of files. (Ch7)
- **HEAD**: a symbolic ref to the branch you are on. It becomes the parent of the next commit. (Ch3, Ch7)
- **hook**: a script in `.git/hooks` that runs on an event. Client hooks are not cloned; server hooks (`pre-receive`, `update`, `post-receive`) can enforce policy. (Ch8)
- **index / staging area**: a file in the Git directory recording the proposed next commit. (Ch1, Ch7)
- **index stages**: during a conflict, stage 1 = common ancestor, 2 = ours, 3 = theirs. (Ch7)
- **integration-manager workflow**: a canonical repo plus a public clone per developer. The maintainer pulls from contributors. (Ch5)
- **JGit / Libgit2 / go-git / Dulwich**: embeddable Git implementations for Java, C (with bindings such as Rugged, LibGit2Sharp and pygit2), Go and Python. (App B)
- **lightweight tag**: a plain pointer to a commit, like a branch that never moves. (Ch2)
- **loose object**: one zlib-compressed file per object under `.git/objects/xx/`. (Ch10)
- **mbox**: a plain-text mailbox format that `git format-patch` writes and `git am` reads. (Ch5)
- **merge-base**: the common ancestor of two branches. `git diff A...B` diffs B against it. (Ch5)
- **merge commit**: a commit with more than one parent, produced by a three-way merge. (Ch3)
- **ours strategy vs -Xours**: `-s ours` records a merge while keeping the current tree exactly. `-Xours` only resolves conflicting hunks in your favour. (Ch7)
- **packed-refs**: the file `git gc` moves refs into. It is checked after `refs/`. (Ch10)
- **packfile (.pack / .idx)**: a single file of delta-compressed objects plus an index of offsets. The newest version of a file is stored whole. (Ch10)
- **patch mode**: hunk-by-hunk selection with `add -p`, `reset -p`, `checkout -p` and `stash -p`. (Ch7)
- **patch-id**: a checksum of only the patch a commit introduces. Rebase uses it to skip commits already applied upstream. (Ch3)
- **pickaxe**: `git log -S <string>`, which finds commits that changed how often a string occurs. (Ch2, Ch7)
- **plumbing vs porcelain**: low-level scriptable commands vs user-facing ones. (Ch10)
- **pull request**: a request to merge a branch, with a discussion and review thread. Exposed as `refs/pull/N/head` and `refs/pull/N/merge`. (Ch6)
- **rebase**: replaying a branch's commits onto another base to get linear history. It creates new commits. (Ch3)
- **reflog**: a local, temporary log of where HEAD and branch tips pointed. Used by `HEAD@{n}` and for recovery. (Ch7, Ch10)
- **refspec**: `[+]<src>:<dst>`, a mapping between remote and local refs for fetch and push. `+` allows non-fast-forward updates. (Ch10)
- **remote-tracking branch**: a local, read-only `<remote>/<branch>` ref recording the remote's state at your last fetch. (Ch2, Ch3)
- **replace ref**: `refs/replace/<sha>`, which makes Git treat one object as another. (Ch7)
- **rerere**: "reuse recorded resolution". Git replays conflict resolutions you made before. (Ch5, Ch7)
- **SHA-1 hash**: the 40-character hex checksum by which Git identifies every object. (Ch1)
- **smart vs dumb HTTP**: smart HTTP negotiates the transfer like SSH and supports auth. Dumb HTTP serves static files and is read-only. (Ch4, Ch10)
- **submodule**: another repository embedded at a pinned commit. `.gitmodules` maps each path to its URL. (Ch7)
- **subtree merge**: merging another project's branch into a subdirectory. (Ch7)
- **symbolic reference**: a ref that contains another ref's name, e.g. HEAD = `ref: refs/heads/master`. (Ch10)
- **tag object**: an object holding tagger, date, message and a pointer to another object. (Ch10)
- **textconv**: a diff-driver setting that converts binary files to text so they can be diffed. (Ch8)
- **three trees**: HEAD (last commit), index (proposed next commit) and working directory (sandbox). This model explains reset and checkout. (Ch7)
- **three-way merge**: a merge that uses the two branch tips plus their common ancestor. (Ch3)
- **topic branch**: a short-lived branch for a single feature or contribution. (Ch3, Ch5)
- **tree**: an object listing mode, type, SHA-1 and name for each blob and subtree. (Ch10)
- **triple dot (A...B)**: commits reachable from either side but not both. (Ch7)
- **working tree**: a single checkout of one version of the project, extracted for editing. (Ch1)
